1. C* 是什么

C*（读作 "C Asterisk"）是一门入门友好的编程语言：

目标怎么做到的
像 C，好迁移大括号、分号、运算符都和 C 一样
关键字看得懂print 打印、int 整数、function main() 主程序、if/for/while 照旧
两种写法，从简到繁代码视图写 .cask，积木视图拖积木，两个视图随时切换（见 3.4）
运行安全溢出、除零、数组越界都会报错并指出出错行，而不是乱算或崩溃
整洁易懂局部变量自动初始化为 0 / 空，先用后赋不会读到垃圾值
名字好写变量名、函数名可以用中文（number 苹果 = 3;）
跑得快.cask 直接生成 x86-64 汇编，再用 as + ld 链接成原生 exe（不经过 C 编译器）

一个完整的例子：

// guess.cask -- 猜数字
function main() {
    int secret = now() % 100 + 1;
    int guess = 0;
    print "我想了一个 1 到 100 的数，猜吧！";
    while (guess != secret) {
        input guess;
        if (guess < secret) { print "小了"; }
        else if (guess > secret) { print "大了"; }
    }
    print "猜对了！";
}

2.1 需要什么

  • Windows 10/11（也支持 Linux/macOS，路径按 / 处理）
  • binutils（as / ld；MinGW-w64：Dev-C++、MSYS2、w64devkit、Strawberry Perl 里都自带）。

2.3 构建

build.bat

会依次生成 bin\caskc.exe（编译器）、bin\libcastrt.a（预编译运行时）、 bin\caskide.exe（编辑器），并把 libgcc.a、cask_rt.h、三个 .cash 头和编辑器界面 （web\ → bin\web\、WebView2Loader.dll）复制进 bin\。 构建工具链需要 gcc 和 g++；但用户编译 .cask 时只需要 as / ld， 链接的是已经编好的 libcastrt.a，不会再调用 C 编译器。 运行测试用：

run_tests.bat

重新生成网页版说明书（需要 Python 3）：

python docs\md2html.py

它会把 docs\ 下的每一本 .md 都生成同名的 .html（手册固定叫 manual.html）： 小学版教程、初中版教程、普高教材必修一、普高选修一、高职教程，一次全部更新。 想检查教材里每个完整例子是否都能编译（窗口程序只编译、不运行，免得弹出窗口），可以跑：

python docs\check_doc_code.py docs\小学版教程.md

build.bat 还会把 cask_rt.h、C_OPED.cash、C_CSS.cash、C_IO.cash、C_OS.cash、 C_NET.cash、C_SC.cash 和 libcastrt.a 复制到 bin\。这些文件必须和 caskc.exe 放在一起， 编译出来的程序才跑得起来。

3. 快速上手

3.1 第一个程序

新建文件 hello.cask：

function main() {
    print "Hello, world!";
}

命令行编译并运行：

bin\caskc.exe hello.cask --run

看到 Hello, world! 就成功了。--run 会先编译再运行；不加 --run 则只编译出 hello.exe。

老写法 start { say "Hello, world!"; } 效果完全一样，say = print、start { } = function main() { }。

3.2 编译器常用命令

bin\caskc.exe 程序.cask              :: 编译成 程序.exe（生成 .s 后调用 as + ld）
bin\caskc.exe 程序.cask --run        :: 编译完立刻运行
bin\caskc.exe 程序.cask --console    :: 窗口程序里保留黑色控制台（方便 print 调试）
bin\caskc.exe 程序.cask -o 我的.exe  :: 指定输出文件名
bin\caskc.exe 程序.cask --emit-c 文件.c  :: 只写出生成的 C 代码（调试用，不编译）
bin\caskc.exe 程序.cask --keep       :: 编译成功后保留生成的 .s 汇编文件
bin\caskc.exe 程序.cask --fast       :: 关闭运行时检查（更快，但不安全）
bin\caskc.exe 程序.cask -g           :: 保留生成的 .s 汇编文件
bin\caskc.exe 程序.cask -v           :: 显示内部执行的 as / ld 命令行
bin\caskc.exe 程序.cask --check      :: 只检查不编译（不留下任何文件），有错退出码非 0
bin\caskc.exe 程序.cask --check --diag :: 再把每条问题按 P|行|列|信息 打出来

--diag 是给编辑器看的机器格式，一条问题一行，行首一个字母分级别：

字母级别意思
E严重程序跑不起来（语义错误：未定义的名字、类型不符……）
S语法写法不对（少分号、括号不配对……），多数会自动"跳过错的地方"继续检查，一次报多条
P拼写名字打错了，后面附"是不是想写 ×××"的建议（只在明显像的时候给）
H提示老写法的提醒（比如还在用 say），不算错误

3.3 C* Studio 编辑器

双击 bin\caskide.exe 就打开编辑器（也可以把 .cask 文件名跟在后面：bin\caskide.exe 我的.cask）。 界面是 Visual Studio 2026 深色风格：顶部菜单栏（文件 / 编辑 / 视图 / 生成 / 调试 / 帮助）、 工具栏、文档标签页、下面停靠的「输出」「问题」工具窗口、底部蓝色状态栏——位置和 VS 一样，上手不费劲。 编辑器界面是一页网页，但它装在一个真正的 Windows 窗口里——程序在本机自己起了个小服务 （只认 127.0.0.1，不连外网），把 bin\web\ 里的页面喂给窗口，所以既好看又好用。 万一 Windows 缺少 WebView2 组件（一般都自带），它会提示你，并改用默认浏览器打开同一界面，功能一样。

边写边查：停下打字约半秒，编辑器就在后台悄悄跑一遍 --check， 底下「问题」面板列出每一条，行号栏上标出错的行；顶部四个小圆点实时计数：

  • 严重（红）——程序跑不起来的问题
  • 语法（橙）——写法不对；编译器会自动跳过错的地方，一次给你看多条
  • 拼写（绿）——名字打错了，会附"是不是想写 ×××"
  • 提示（蓝）——只是建议（比如你还在用老写法 say），不算错误

运行：按 F5 → 下面出现「输出」面板。编译有问题就停在问题面板；没问题就跑起来， 程序 input 的时候面板里出现输入框，打字按回车喂给程序；结束时显示 [结束，退出码 0]。 状态栏右侧依次是：文件名（改过会亮一个 ●）、编码、当前行列、四个计数、版本号。

保存编码放在菜单栏「编辑」里的 转成 UTF-8（推荐） / 转成 GBK（给老环境） 两项， 用来立刻换一种编码保存当前文件（例如把别人给的 GBK 文件转成 UTF-8， 好让中文变量名能被编译器接受）。工具栏上的「编码 ▾」按钮做的是同一件事。

变量名是亮蓝（不是上面任何一类）；当前所在行有一道淡蓝横条； 光标停在某个括号上时，配对的括号会一起描灰边——这几个和 Visual Studio 一样。

注释（// … 和 /* … */）用 VS Code 那样的绿色斜体，在积木视图里也是一块能点改的绿色积木。

鼠标停在词上会告诉你它是干什么的：旁边冒出一张小卡片，上排是这个函数的写法， 下排是说明。停在 print 上是 print 值1, 值2 …;——"打印这些值，打印完换行"； 停在 LEN 上是 LEN(文字)——"文字长度。按字节算，一个汉字算 3"。 忘了哪个函数怎么用，鼠标停一下就行。

选中的文字用半透明的蓝底，底下的彩色文字照样看得清；左边行号栏上出错的行标红。 Tab 缩进、回车自动对齐空位（上一行有 { 会自动多缩一层）。 UTF-8 和系统编码（如 GBK）保存的 .cask 都能正确打开和保存。

也可以直接把它拖到画布上想要的位置松开。

  • 往括号里加东西：括号里那个小小的黄色 ＋ 就是干这个的。空括号里点它

（比如 function 打招呼()），敲 string 名字 回车，就成了 function 打招呼(string 名字)； 已经有内容的括号末尾也有一个 ＋，点它再敲一个参数，逗号会自动补上： 接着敲 int 年龄，就成了 function 打招呼(string 名字, int 年龄)。 入口 function main() 的括号例外——main 不能带参数，所以那里没有 ＋（见 4.7 与第 6 章）。

剪切则移除）、Ctrl+V 粘贴到选中积木后面（没选中就进 main 里）。

  • 撤销 / 重做：Ctrl+Z 撤销上一步、Ctrl+Y（或 Ctrl+Shift+Z）重做；积木视图里每次

增删、改格子、拖放都记进历史，可以连退几步再连进几步（代码视图里 Ctrl+Z 直接走编辑框自己的撤销）。

  • 语句按嵌套一层层缩进，带身体的判断/循环画成包住身体的 C 形。
  • 注释积木：// … 和 /* … */ 会画成一条绿色的斜体积木，显示注释原文；

点它就能就地改写（写正文会自动补上 //），所以注释在积木视图里也能改、能删、能拖动。

  • use 积木拉线：一条 use "头文件"; 积木右边会拉出一条线，连到画布右侧一个独立信息方框，

方框里写这个头文件的名字、一句话概述、依赖（要先 use 谁）和「已扫描」状态； 这个方框在所有积木框外面，线从 use 积木右边缘穿过去连到它。

重要：积木视图和代码视图是同一个程序——积木里做的每个动作都会立刻改写代码文本， 再重新解析成积木。也就是说，代码永远是真身，积木只是它的一种好看的样子； 两边永远不会"对不上"。注释行和空行在积木视图里会藏起来（免得乱），切回代码视图还在。

积木视图能显示的是语句级结构（一块积木 = 一条语句）。想写复杂表达式， 改积木上的黄色格子（那是一整段代码文字），或者切回代码视图直接写——两种办法等价。

8. 常见问题

Q：提示 找不到 'C_OPED.cash'？ 把 C_OPED.cash 放在 caskc.exe 同目录（build.bat 已自动复制到 bin\）， 或设置环境变量 CASK_RT_DIR 指向那个目录。

Q：窗口程序运行起来没有黑窗口，print 看不见？ 窗口程序默认是"窗口式"的，没有控制台，所以 print 的输出没地方显示。 调试时加 --console（或干脆用 alert() / 标签显示结果）：

bin\caskc.exe 我的窗口.cask --run --console

Q：编译时提示找不到 as / ld？ 把 binutils 所在目录（MinGW-w64 的 bin）加进 PATH，或直接用 Dev-C++ 自带的 binutils。 编译 .cask 不需要 gcc；gcc 只在构建工具链本身时用到。

Q：提示 找不到 cask_rt.h？ 把 cask_rt.h 放在 caskc.exe 同目录（build.bat 已自动复制），或设置环境变量 CASK_RT_DIR 指向它。

Q：中文输出乱码？ 源文件保存为 UTF-8，C* 会自动把控制台切到 65001 代码页；保存为 GBK 也可以，程序会用默认代码页。两者不要混。

Q：想用中文当变量名、函数名？ 可以，例如 int 苹果 = 3;、function 打招呼(string 谁) { … }。 要求文件保存为 UTF-8；如果存成了别的编码，编译器会提示 名字里有非 ASCII 字母，文件要存成 UTF-8。 （C\* Studio 状态栏会显示当前文件是 UTF-8 / ASCII / GBK； 如果文件是 GBK，用菜单栏「编辑 → 转成 UTF-8（推荐）」一键转换。） 纯英文的（ASCII）文件会自动按 UTF-8 保存，所以以后加中文名字不会有问题。

Q：积木视图和代码视图会不会不一致？ 不会。积木是从代码文本解析出来的视图，你对积木的每次操作（拖入/删除/移动/双击改内容） 都是立刻改写代码文本再重新解析。代码是唯一的真身，随时可以切回代码视图核对。

Q：string 能不能 t[0] = 'X'; 这样改一个字？ 不能（这是有意的简化）。用拼接：t = 前缀 + "X" + 后缀，或改用 char arr[] 数组。

Q：还写着 number，会不会哪天不能编译了？ 不会。number / real / text / letter 是软弃用别名，一直能编译； 只是 --check --diag 和 C\* Studio 的「问题」面板会给你一条 H（提示），建议换成新名字。 老项目可以慢慢改，不用一次性大改。

Q：常量报"必须是……表达式"？ 常量是编译期求值的，只能放字面量、算术和其它常量；要运行期算的值请用普通变量。

Q：想看等价的老式 C 代码？ bin\caskc.exe 程序.cask --emit-c out.c 会写出一份仅供阅读的 C 参考代码； 正常编译走汇编后端，不产生 C，也不调用 C 编译器。想看真正生成的汇编用 --keep。
