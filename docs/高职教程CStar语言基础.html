1.3 第一个程序

一个 C* 程序从 function main() 开始执行。下面是最小的完整程序：

// hello.cask -- 第一个 C* 程序
function main() {
    print "你好，C*！";
    print "这是我的第一个程序。";
}

运行结果：

你好，C*！
这是我的第一个程序。

三个要点：

  • function main() { } 是入口，程序从这里第一行开始跑。每个程序只能有一个。
  • print ...; 是输出语句，打完之后自动换行。一句话结束要有分号 ;。
  • // 后面是注释，写给同学和以后的自己看，编译器不看。

想不换行地输出（比如"请输入："），用 show：

// 输出小例子
function main() {
    show "请输入你的名字：";
    print "（这一行是接着上一行打的）";
}

运行结果：

请输入你的名字：（这一行是接着上一行打的）

1.5 从 .cask 到 .exe，中间发生了什么

在命令行里可以自己看一眼这中间的过程。下面命令里的 程序.cask 换成你自己的文件名：

bin\caskc.exe 程序.cask                 :: 编译出 程序.exe（默认带完整检查）
bin\caskc.exe 程序.cask --run           :: 编译完立刻运行
bin\caskc.exe 程序.cask -o 我的.exe      :: 指定输出的 exe 名字
bin\caskc.exe 程序.cask --check         :: 只检查，不生成任何文件
bin\caskc.exe 程序.cask -v              :: 显示真正执行的 as / ld 命令
bin\caskc.exe 程序.cask -g             :: 保留生成的 .s 汇编文件
bin\caskc.exe 程序.cask --emit-c 文件.c  :: 只写出一份等价的 C 代码（对照用，不编译）

真正生成 .exe 的路径是：.cask 直接生成 x86-64 汇编（.s），再用 as 汇编、用 ld 链接上预编译好的运行时库 bin\libcastrt.a，全程不调用 C 编译器。-v 能看到这两条命令。--keep / -g 留下中间那份 .s 汇编；--emit-c 文件.c 则是另写一份等价的 C 代码——只为对照、调试，正常编译不会用到它。第一章先知道有这回事，附录 C 会讲 C* 和 C 的对照关系。

任务实施

任务：做一张会打印在屏幕上的自我介绍卡片。

第 1 步　新建文件。 在编辑器里按 Ctrl+N，工具栏点"保存"，文件名叫 card.cask。后缀一定要是 .cask。

第 2 步　写代码。 逐行敲进下面的内容。注意标点全部用英文半角：分号是 ; 不是 ；，引号是 " 不是 “ ”。

// card.cask -- 自我介绍卡片
function main() {
    print "===== 自我介绍 =====";
    print "姓名：李明";
    print "专业：软件技术";
    print "班级：软件 2401";
    print "爱好：打篮球、写代码";
    print "===== 谢谢观看 =====";
}

第 3 步　运行。 按 F5。输出面板里应该出现：

===== 自我介绍 =====
姓名：李明
专业：软件技术
班级：软件 2401
爱好：打篮球、写代码
===== 谢谢观看 =====

第 4 步　在命令行里跑一遍。 打开命令行，cd 到 C_AS 目录：

bin\caskc.exe card.cask --run

看到的输出和编辑器里一样。

第 5 步　故意写错一次，认识报错。 把第 3 行的分号删掉，再按 F5。问题面板会出现一条语法问题，大意是这一行少了分号。这就是"语法"级。

再把 print 写成 prnt，问题面板给出的是"拼写"级，还会问你"是不是想写 print"。

第 6 步　看一眼等价的 C（对照用）。 在命令行里：

bin\caskc.exe card.cask --emit-c card.gen.c

旁边会多出一个 card.gen.c。打开看一眼前面的几行就能看到：print "..." 变成了 cask_p_str("...") 加一个换行。不用看懂细节，知道有这么回事就够了。

记住：--emit-c 只是把程序翻成一份等价 C 给你看，正式生成 .exe 走的是另一条路——直接产出 x86-64 汇编，再用 as + ld 链接（见 1.5 节）。

拓展与规范

命名规范。 变量名、函数名用"看得懂"的名字：总分、平均分、isPassed 都比 a、b、x1 好。小写英文加下划线、或者直接用中文，两种都行，一个项目里保持统一。名字不能以数字开头。

注释。 // 写一行注释，/* 多行 */ 写多行。注释写"为什么这么做"，不要复述代码：

// 不好：把分数加进去
// 好：这里按 60 分算及格（教务规定）
总分 = 总分 + 分数;

缩进。 一个大括号里缩进四格。工具栏的"格式化"按钮能一键理清缩进，写完点一下再交。

保存编码。 文件保存为 UTF-8。想用中文变量名就必须是 UTF-8。工具栏"编码 ▾"里可以一键"转成 UTF-8"。

中文标点是最常见的入门坑。 输入法在中文状态下打出的 ；、，、“ ”、（） 都不是 C* 的符号。全角分号会报语法错误，全角引号会让编译器把一整段当成一个没见过的名字。

别把变量名写成关键字。 int print = 1; 不行，print、if、for、int 这些是关键字，还有 IF、SUM、LEN 这些内置函数名也不能当变量名。

一个程序只能有一个 function main()。 多了会报错。

2.4 类型转换

C* 的类型转换规则很短，记住两条：

  • int 可以自动变成 float：float 小 = 3; 得到 3。
  • float 不能自动变成 int：int 整 = 3.5; 会报严重错误 不能把 float 放进 int。想转必须自己写清楚是"向下取整"还是"四舍五入"。
// 转换小例子
function main() {
    float 单价 = 19.9;
    int 元 = INT(单价);          // 向下取整：19
    int 凑整 = ROUND(单价);       // 四舍五入：20
    float 小数部分 = 单价 - 元;

    print "INT 得到 ", 元;
    print "ROUND 得到 ", 凑整;
    print "小数部分 ", 小数部分;
}

运行结果：

INT 得到 19
ROUND 得到 20
小数部分 0.899999999999999

最后一行值得停一下：19.9 减去 19 按理是 0.9，为什么打出 0.899999999999999？因为小数在计算机里是用二进制近似存的。比较小数不要用 ==，要用差值的绝对值小于一个很小的数来判断：

// 小数不能直接比相等
function main() {
    float a = 0.1 + 0.2;
    if (a == 0.3) { print "相等"; }
    else { print "不相等，差 ", a - 0.3; }

    if (ABS(a - 0.3) < 0.000001) { print "在误差范围内算相等"; }
}

运行结果：

不相等，差 5.55111512312578e-17
在误差范围内算相等

拓展与规范

声明和赋值分开写还是合起来写。 本项目里 string 姓名; input 姓名; 是分开的，因为要读入的值必须在 input 之前先声明好。如果初值确定，就直接写在一起：int 满分 = 100;。

小数打印的真相。 C* 打印小数时保留 15 位有效数字：

代码打印结果原因
print 2.0;2末尾的 .0 不打印

常见坑清单：

  • int 整 = 3.5; → 严重错误。要写 INT(3.5) 或 ROUND(3.5)。
  • char c = "A"; → 严重错误。字符用单引号。
  • string s = 'A'; → 严重错误。字符串用双引号。
  • constant int N = 满分 + 1;（满分 是变量）→ 报"常量必须是能算出来的表达式"。
  • 在函数里写 constant → 报错，常量只能写在最外层。
  • print 1.0 / 3; → 得到 0.333333333333333，但 print 1 / 3; 得到 0：两个整数相除是整数除法，小数部分直接丢掉。想要小数结果，除号两边至少有一个是小数。

知识准备

4.1 if / else if / else

// 多分支判断
function main() {
    int 分数 = 78;
    if (分数 >= 90) { print "优秀"; }
    else if (分数 >= 80) { print "良好"; }
    else if (分数 >= 70) { print "中等"; }
    else if (分数 >= 60) { print "及格"; }
    else { print "不及格"; }
}

运行结果：

中等

规则：

  • if 后面的括号里必须是比较结果（bool）。
  • 从上到下依次判断，第一个成立的分支执行后，后面的全部跳过。所以上面的写法里 分数 >= 70 不用再写"且小于 80"，因为到这儿就说明前面两条都不成立。
  • else 最多一个，写在最后。
  • 判断同一个变量的多个区间，if/else if 的顺序很重要：从大到小排，别把 >= 60 写在 >= 90 前面。

4.2 switch

当判断条件是"某个整数等于几个固定值之一"时，switch 比一串 else if 清楚。

// switch 分档
function main() {
    int 分数 = 95;
    int 档位 = 分数 / 10;
    switch (档位) {
        case 10:
        case 9:  print "优秀"; break;
        case 8:  print "良好"; break;
        case 7:  print "中等"; break;
        case 6:  print "及格"; break;
        default: print "不及格"; break;
    }
}

运行结果：

优秀

规则：

  • switch 后面的括号里必须是整数（int）。
  • case 后面必须是编译时能算出值的常量：字面量、constant、四则运算。不能写变量。
  • 一个 case 后面不写语句，就直接落到下一个 case（上面的 case 10: 就是这种情况）。
  • 每个分支最后要写 break; 跳出，不写会继续往下执行别的分支。这是最容易错的细节。
  • default: 最多一个，可以省略。

4.3 while 和 for

// 两种最常用的循环
function main() {
    int 总和 = 0;
    int i = 1;
    while (i <= 100) {
        总和 = 总和 + i;
        i++;
    }
    print "1 加到 100 = ", 总和;

    int 阶乘 = 1;
    for (int k = 1; k <= 5; k++) {
        阶乘 = 阶乘 * k;
    }
    print "5! = ", 阶乘;
}

运行结果：

1 加到 100 = 5050
5! = 120

for 括号里是三段，用分号隔开：

位置作用常见写法
第一段初始化，只执行一次int i = 1
第二段条件，每轮开始前检查i <= 10
第三段每轮结束后执行i++

三段都能省略：for (;;) { ... } 就是死循环（要靠 break 出来）。

for 的循环变量有个坑。 for (int i = 0; ...) 里的 i 属于外层那个大括号的作用域，不是这个 for 私有的。所以在同一层里写两个 for (int i = ...) 会报"i 已经声明过了"。两种改法：循环变量改用不同的名字；或者先声明 int i;，两处都写 for (i = 0; ...)；或者给第二个循环套一层 { }。

4.4 do…while 和 until

这两个都是先做一次，再判断。

// 至少执行一次的循环
function main() {
    int n = 10;

        n++;
    } while (n < 3);

运行结果：

until 里的 m = 0
until 里的 m = 1
until 里的 m = 2
结束，m = 3
  • do { } while (条件); 结尾有分号。条件成立就继续。
  • until (条件) { } 和 while 正好相反：条件成立就停。适合"一直做到满足要求为止"的说法。
  • 两者的循环体都至少执行一次，因为条件是在第一次做完之后才检查的。

循环什么时候用

第 4 步　看懂这段程序的骨架。

  • 外层是一个 while：只要不是 -1 就继续读。这是"录到哨兵值为止"的标准写法。
  • 里层是一个 if/else：先判断合法性，再决定统计还是提示。先校验再使用，这是数据录入程序的基本纪律。
  • 统计放在循环里面，因为每读一条就要累计一次。
  • 打印放在循环外面，因为要等录完了才有完整结果。

拓展与规范

判断区间从大到小排。 if (分数 >= 90) ... else if (分数 >= 80) ... 这样写，条件互不重叠，不会漏。把顺序写反会出现"所有人都是及格"的荒唐结果。

while 里一定要有让条件变化的语句。 忘了写 i++，程序会一直转，编辑器里按 Esc 才能停。

for (;;) 配上 break 是"不知道要转多少圈"时的常用写法，但 break 的条件必须写在显眼的开头。

switch 的 break 不能忘。 忘了写，程序会穿过这个分支继续执行下面的分支。

foreach 只给小名。 循环变量不写类型；而且它属于外层块，同一层里别再用同名变量。

输入循环要能退出。 用户输错格式时 input 会要求重输；用哨兵值（比如 -1）结束循环比"输入一个非数字去猜"更可靠。

先写骨架，再填肉。 拿到题目先写循环和外层判断，跑一遍看看流程对不对，再往里填统计语句。一次写 30 行再跑，出错很难定位。

本章小结

  • if / else if / else 从大到小排区间；条件必须是 bool。
  • switch 用于整数对若干常量；case 后必须是常量，分支末尾写 break;。
  • while 次数不定，for 次数明确，do…while 和 until 至少执行一次，foreach 遍历一维数组。
  • for (int i = ...) 里的 i 属于外层作用域，同一层不要重复声明。
  • foreach (x in 数组) 的循环变量不写类型。

知识准备

5.1 定义函数：返回值类型写在前面

格式是 返回类型 函数名(参数表) { 函数体 }：

// 有返回值的函数
float 平均分(int 总分, int 人数) {
    return 总分 * 1.0 / 人数;
}

string 评级(float 分) {
    if (分 >= 90) { return "优秀"; }
    if (分 >= 60) { return "及格"; }
    return "不及格";
}

function main() {
    int 总分 = 268;
    int 人数 = 3;
    float 平均 = 平均分(总分, 人数);
    print "平均 ", ROUND(平均, 1);
    print "评级 ", 评级(平均);
    print "另一个 ", 评级(95.0);
}

运行结果：

平均 89.3
评级 及格
另一个 优秀

四条规则：

  • 返回值的类型写在函数名前面，这是 C* 的规定，也是 C 的写法。要返回整数就写 int，要返回小数写 float，要返回文字写 string。
  • return 值; 一旦执行，函数立刻结束，后面的语句不再执行。所以 评级 里三个 return 只会跑一个。
  • 参数表里每个参数都要写类型：(int 总分, int 人数)，不能只写 (总分, 人数)。
  • 函数可以先用后定义：写在 main 后面也行，编译器会先把整个文件扫一遍。

5.2 不返回值的函数

只"做一件事"、不需要交结果的函数，有两种写法，效果一样：

// 不返回值的函数
none 打横线(int 个数) {
    string 线 = "";
    for (int i = 0; i < 个数; i++) {
        线 = 线 + "-";
    }
    print 线;
}

function 打印标题(string 标题) {
    print "=== ", 标题, " ===";
}

function main() {
    打横线(20);
    打印标题("成绩单");
    打横线(20);
}

运行结果：

--------------------
=== 成绩单 ===
--------------------
  • 写 none 开头的函数不能 return 值;，但可以写 return; 提前结束。
  • 写 function 开头的函数同样不返回值。两种写法完全等价，本书统一用 none 表示"不返回值的函数"，用 function main() 表示入口。

5.3 参数是按值传的

调用函数时，参数的值被复制一份送进去。函数里改的是那份拷贝，外面的变量不受影响。

// 参数是按值传递的
none 改一改(int x) {
    x = x * 10;
    print "函数里面 x = ", x;
}

function main() {
    int n = 5;
    print "调用前 n = ", n;
    改一改(n);
    print "调用后 n = ", n;
}

运行结果：

调用前 n = 5
函数里面 x = 50
调用后 n = 5

想让函数"改外面的东西"，用 return 把结果交回去，再在外面赋值：

// 通过返回值把结果交回去
function main() {
    int n = 5;
    n = 加十倍(n);
    print "n = ", n;
}

int 加十倍(int x) {
    return x * 10;
}

运行结果：

n = 50

5.4 作用域

名字写在哪谁能看见
函数里的 { } 中只在那个 { } 里看得见，出了大括号就没了
所有函数外面（最外层）这叫全局变量，写在它前面的所有函数都能读写
// 全局变量与局部变量
int 累计 = 0;                     // 全局变量：写在最外层

none 记一笔(int 金额) {
    累计 = 累计 + 金额;            // 函数里可以直接改全局变量
    print "这一笔 ", 金额, "，累计 ", 累计;
}

function main() {
    记一笔(100);
    记一笔(50);
    print "总计 ", 累计;
}

运行结果：

这一笔 100，累计 100
这一笔 50，累计 150
总计 150

两个容易踩的地方：

  • 全局变量要写在用它的函数前面。 把 int 累计 = 0; 挪到文件最后，程序编译不过。C* 生成 C 时是按顺序排的，和 C 的规则一样。
  • 内层可以起和外层一样的名字，内层的会"遮住"外层的。这不是好习惯，正式项目里尽量避免。

5.5 递归：函数自己叫自己

函数体里调用自己叫递归。递归必须有出口，否则会一直往下叫。

// 递归求阶乘
int 阶乘(int n) {
    if (n <= 1) { return 1; }
    return n * 阶乘(n - 1);
}

function main() {
    for (int i = 1; i <= 6; i++) {
        print i, "! = ", 阶乘(i);
    }
}

运行结果：

1! = 1
2! = 2
3! = 6
4! = 24
5! = 120
6! = 720

写递归时先写出口（if (n <= 1) { return 1; }），再写"把问题缩小一步"的那句，顺序不要倒。

5.6 数组暂时不能当参数

C* 0.5.0 里函数参数不能是数组。写下 int 求和(int 数据[4]) 会直接报错：

错误: 还不支持数组参数（v0.1）

替代办法有三个：

  • 用内置的汇总函数：SUM(数组)、AVERAGE(数组)、MAX(数组)、MIN(数组)、COUNT(数组)。
  • 把数组写成全局变量，函数里直接按名字访问。
  • 把循环写在调用处，不封成函数。
// 用全局数组代替"数组参数"
int 分数[5] = {88, 95, 72, 66, 91};

float 平均() {
    return AVERAGE(分数);
}

function main() {
    print "本班平均 ", 平均();
    print "本班最高 ", MAX(分数);
}

5.7 use：把 C 的头文件引进来

use 做的事就是 C 的 #include：把另一个文件的内容包含进程序。

use "my_lib.h";                 // 引号：先在本目录（exe 所在目录）找
use <stdio.h>;                  // 尖括号：在编译器自带的系统目录里找

尖括号引的是系统头文件。引号引的是自己写的头文件，放在 .cask 旁边即可——因为不带 -o 时，生成的 exe 就在 .cask 同一个目录里。

自己写的头文件里可以放函数。要让编译器认得出里面那个函数，需要在 .cask 里补一行函数原型，参数类型要写得和 C 一致：int 对应 C 的 long long。

use "my_lib.h";                 // 先把头文件引进来

int double_it(int x);           // 再声明头文件里那个函数的原型

配套的 my_lib.h 内容：

/* my_lib.h -- 自己写的小工具头文件 */
static long long double_it(long long x) { return x * 2; }

在程序里就可以像自己的函数一样调用 double_it(21)，结果是 42。

三条要注意的：

  • 头文件里的函数必须先声明原型再调用。忘了写，编译器会提示 不认识的函数 ...（如果它来自 'use' 的头文件，请先声明: int ...(...);），照着提示补一行就行。
  • 头文件里的 #define 宏不能直接当变量名用。要固定的值，在自己的 .cask 里写 constant。
  • 头文件路径是相对生成的 exe 的目录算的。用了 -o 别的目录\程序.exe，头文件也要放到那个目录里。

系统头文件里的函数怎么用，第 11 章会用完整的例子讲（那一章还要引 C_OPED.cash）。

  • 定义格式：返回类型 函数名(参数表) { ... }，用 return 交结果；不返回值用 none 或 function 开头。

  • 局部变量出了 { } 就失效；全局变量写在最外层，而且必须在用它之前。
  • 递归要有出口，先写出口再写递归调用。
  • 函数里不能传数组，用 SUM/AVERAGE/MAX/MIN/COUNT 或者把数组放全局。

6.2 遍历：for 和 foreach

// 两种遍历方式
function main() {
    int 分数[6] = {72, 95, 60, 88, 95, 77};

    int 总 = 0;
    int 最高 = 分数[0];
    for (int i = 0; i < 6; i++) {
        总 += 分数[i];
        if (分数[i] > 最高) { 最高 = 分数[i]; }
    }
    print "总分 ", 总;
    print "平均 ", ROUND(总 * 1.0 / 6, 1);
    print "最高 ", 最高;

    print "依次列出：";
    foreach (x in 分数) {
        show x, " ";
    }
    print "";
}

平均 81.2
最高 95
依次列出：
72 95 60 88 95 77

要下标（比如"改第 3 个"、"找位置"）就用 for；只关心值就用 foreach。

同样这几件事，内置函数一行就够，可以拿来核对：

// 内置汇总函数对照
function main() {
    int 分数[6] = {72, 95, 60, 88, 95, 77};
    print "总和 ", SUM(分数);
    print "平均 ", AVERAGE(分数);
    print "最高 ", MAX(分数);
    print "最低 ", MIN(分数);
    print "个数 ", COUNT(分数);
}

运行结果：

平均 81.1666666666667
最高 95
最低 60
个数 6

6.4 排序：冒泡排序

思路：从第一个元素开始，相邻两个比大小，大的往后换；走完一趟，最大的就"冒"到了最后。重复若干趟，全部有序。

// 冒泡排序：从小到大
function main() {
    int 分数[6] = {72, 95, 60, 88, 95, 77};
    for (int i = 0; i < 5; i++) {
        for (int j = 0; j < 5 - i; j++) {
            if (分数[j] > 分数[j + 1]) {
                int 临时 = 分数[j];
                分数[j] = 分数[j + 1];
                分数[j + 1] = 临时;
            }
        }
    }
    foreach (x in 分数) { show x, "  "; }
    print "";
}

运行结果：

60  72  77  88  95  95

外层要从大到小排，把 > 改成 < 即可。交换两个值必须先存到临时变量里，写成 分数[j] = 分数[j + 1]; 分数[j + 1] = 分数[j]; 会把第一个值覆盖掉。

6.5 查找：顺序查找

// 顺序查找
function main() {
    int 分数[6] = {72, 95, 60, 88, 95, 77};
    int 目标 = 88;
    int 位置 = -1;
    for (int i = 0; i < 6; i++) {
        if (分数[i] == 目标) {
            位置 = i;
            break;
        }
    }
    if (位置 >= 0) {
        print "找到 ", 目标, "，下标 ", 位置, "，是第 ", 位置 + 1, " 个";

第 4 步　注意 i 和 j 的声明位置。 上面的程序把 int i; 和 int j; 提到最前面，几处循环共用。这不是为了好看，而是因为 for (int i = 0; ...) 里的 i 属于外层作用域，同一层里声明第二次会报错（见"拓展与规范"）。

拓展与规范

下标从 0 开始，长度是"个数"。 int a[5] 的合法下标是 0 到 4。写循环用 i < 5，别写 i <= 5。

长度用常量。 把 50 写成 constant int 最多人数 = 50;，以后要改只改一处，长度和循环条件都跟着改。

for 的循环变量重复声明会报错。 原文是 'i' 在这里已经声明过了。三种改法：起不同的名字、先声明后用 for (i = 0; ...)、或者给第二个循环套一层 { }。

foreach 的循环变量不写类型。 写 foreach (int x in 数组) 会报"这里要写循环变量名"。

排序时"一起换"。 姓名和分数是两个数组，交换分数时必须同时交换姓名，否则名单和分数会对不上。这类"平行数组"是数组入门阶段的常态。

越界的错误信息很直白。 见到 C* 运行错误: 数组下标越界，去信息里给的行号，检查那一行的下标表达式。常见原因是循环用了 <=，或者下标是算出来的、算大了。

字符串拼接在循环里要小心效率。 一次拼几百个字符没问题；拼几万次会很慢。数据量大时改用 memo 一次性输出。

中英混排的宽度。 LEN("中文A") 是 7（3+3+1），不是 3。要按"显示宽度"排版，得自己把汉字按 2 个宽度算。

本章小结

  • 数组 类型 名字[长度]; 或 类型 名字[长度] = {…};，下标从 0 到长度减 1，越界会报错。
  • 不写初值时所有元素自动为 0（string 为空文字）。
  • for 要下标，foreach 只取值（循环变量不写类型，只支持一维数组）。
  • SUM/AVERAGE/MAX/MIN/COUNT 传一维数组名，省掉手写循环。
  • 冒泡排序：相邻比较、交换，外层轮数 长度-1；交换必须用临时变量。
  • 顺序查找：用 位置 = -1 表示没找到。
  • 字符串用 + 或 CONCAT 拼接，== 比内容，LEN/LEFT/MID/at 按字节计数，一个汉字 3 个字节。

7.1 菜单循环的骨架

菜单程序的结构就是"打印菜单 → 读一个选择 → 分支处理 → 回到开头"。用一个 while 加一个 if/else if 链就够。

// 菜单循环的骨架（用数组模拟"用户依次输入的选择"）
function main() {

函数不能接收数组，所以名单数据只能是全局数组，所有函数按名字直接访问：

数组类型存什么
学号string[50]学号，下标 i 是第 i+1 个学生

string 姓名[4] = {"甲", "乙", "丙", "丁"};

7.3 平均分要在录入时就算好

排序和统计都要用平均分，每次现算很浪费。在录入结束时算好存进 平均 数组，后面所有函数直接用。

none 算平均(int k) {
    int 总 = 0;
    for (int j = 0; j < 课程数; j++) {
        总 += 成绩[k][j];

    平均[k] = 总 * 1.0 / 课程数;
}

总 * 1.0 是把整数转成小数再除，否则整数除法会把小数部分丢掉。

三个参数分别是标题文字、宽度、高度，单位是像素。返回值是"窗口号"，要留着后面用。

use "C_OPED.cash";

8.4 按钮被点了怎么办：on_click

function on_click(int 控件) {
    // 控件 就是被点击的那个控件的编号
}

这个名字是固定的。只要程序里定义了这个函数，用户点任何按钮都会自动调用它，参数是被点控件的编号。所以：

  • 需要一个全局变量保存按钮的编号，事件函数里才能比较。
  • 用 if (控件 == 某个按钮) 判断是哪一个。
use "C_OPED.cash";

int 显示框;
int 次数 = 0;

function on_click(int 控件) {
    次数 = 次数 + 1;
    settext(显示框, "你点了 " + 次数 + " 次");
}

function main() {
    int 窗口 = window("按钮计数器", 480, 300);
    label("点下面的按钮，看看数字怎么变：", 24, 24, 420, 24);
    显示框 = label("你点了 0 次", 24, 56, 420, 24);
    int 按钮 = button("点我", 24, 100, 140, 34);
    run();
}

settext(控件, "文字") 用来改控件上显示的文字。这个程序换成真实的运行效果就是：窗口里有两行文字和一个"点我"按钮，每点一次按钮，第二行文字就变成"你点了 1 次"、"你点了 2 次"……

8.5 多个按钮怎么区分

use "C_OPED.cash";

int 显示框;
int 加按钮;
int 减按钮;
int 计数 = 0;

none 刷新() {
    settext(显示框, "当前计数 " + 计数);
}

function on_click(int 控件) {
    if (控件 == 加按钮) { 计数 = 计数 + 1; }
    if (控件 == 减按钮) { 计数 = 计数 - 1; }
    刷新();
}

function main() {
    int 窗口 = window("加减计数", 480, 300);
    显示框 = label("当前计数 0", 24, 24, 420, 24);
    加按钮 = button("+1", 24, 80, 100, 34);
    减按钮 = button("-1", 140, 80, 100, 34);
    刷新();
    run();
}

要点：

  • 三个控件的编号都存进了全局变量。如果 加按钮 写成 main 里的局部变量，on_click 里就看不见它，没法比较。
  • 把"更新界面"抽成 刷新()，两处按钮都调用它，界面不会出现两套写法不一致的情况。
  • 在 run() 之前先调一次 刷新()，保证窗口一出现就是正确状态。

int 提示标签;
int 状态标签;

int 撤销按钮;
int 清零按钮;

        settext(提示标签, "签到成功！");

拓展与规范

控件号必须存在全局变量里。 这是窗口程序最常见的错误：把 签到按钮 写成 main 里的局部变量，编译不报错，但 on_click 里比较的永远是 0，按钮点了没反应。

事件函数的名字是固定的。 只有 on_click、on_change、on_close 三个名字会被自动调用。写成 onClick、点击 都不会被调用，而且编译器不会提醒你。

同一类事件只写一个函数。 十个按钮也只有一个 on_click，靠 if (控件 == ...) 分派。别指望给每个按钮写一个函数。

控件不要重叠。 后添加的控件会盖住先添加的。坐标算错造成的"按钮点不到"，多半是这个问题。

窗口程序不自动运行（本书的检查流程里）。 因为 run() 会一直等用户关窗口，自动化检查里只做编译。你在本地按 F5 是能正常跑的。

用 alert 代替 print 调试。 没有控制台的时候，print 看不到；alert("到这里了") 会弹框，能确认程序走到哪一步。

编译不过先看问题面板。 窗口程序拼错函数名（比如 lable）会报"未知函数"，并提示相近的名字。

窗口程序不需要 return。 main 结束时窗口已经关了，程序直接退出。

拓展与规范

readtext 拿到的是"当前文字"，每次调用都会重新取一遍。想把输入框清空就 settext(输入框, "")。

数字要从输入框取，得先转换。 readtext 返回的是字符串，要参与计算得用 VALUE 转成数字：

// 把输入框里的文字当数字用
use "C_OPED.cash";

function main() {
    int 窗口 = window("数字转换", 480, 240);

真正计算时写成 int n = VALUE(readtext(输入)); 注意 VALUE 会把小数部分截掉，要小数就先取文字再自己解析。

进度条的范围是 0 到 100。 setvalue(进度条, 150) 不会报错，但显示会停在满格。要显示别刻度，自己换算一下。

sleep 的单位是毫秒。 sleep(1000) 是一秒。界面在做 sleep 期间不会响应点击，别在按钮事件里写太长的 sleep。

on_close 里不要写 sleep 或等待用户的长动作。 它的用途是"记一笔、问一句"。

事件函数里别写长循环。 事件函数要尽快返回，界面才流畅。要处理很多数据，就在按钮事件里算完一次、刷新界面，别在 on_change 里做重活。

10.1 打开文件工具箱：C_IO.cash

在程序最前面写一行：

use "C_IO.cash";

C_IO.cash 不依赖窗口，控制台程序也能用。它提供下面这组函数：

函数作用返回
readfile(路径)把整个文件读成一段文字读不到给 ""，上限 1MB
writefile(路径, 内容)覆盖写入（旧内容整个被换掉）成功 1，失败 0
appendfile(路径, 内容)追加到文件末尾成功 1，失败 0
fileexists(路径)文件或目录在不在在 1，不在 0
makedir(路径)建目录（已存在也算成功）成功 1，失败 0

writefile 是覆盖、appendfile 是追加，这是最容易用混的两个：日志类要留旧内容就用 appendfile，配置类每次整个重写就用 writefile。

10.2 保存和读取设置

下面的程序第一次运行时写入默认设置，以后每次都直接读出来，用户改过的内容不会被覆盖：

// 设置小工具：第一次写默认值，之后读出来用
use "C_IO.cash";

function main() {
    string 文件 = appdir() + "/settings.txt";
    if (fileexists(文件) == 0) {
        writefile(文件, "名字=小明\n内存=2048");
        print "第一次运行，已写入默认设置。";
    }
    print "当前设置：";
    print readfile(文件);
    return 0;
}

逐行看：appdir() 返回 exe 所在目录，拼上 /settings.txt，文件就落在程序旁边（跟着 exe 走，不依赖"当前工作目录"）；fileexists(文件) == 0 表示还没这个文件，这时才写默认值；\n 是换行符，写进文件后 readfile 读出来也带着换行。

Windows 的路径分隔符是 \，但在 C* 字符串里一个反斜杠要写成 \\：

也可以统一写 /，Windows 和 Linux 都认（上面例子里就是 /）。相对路径按当前工作目录解析，不一定等于 exe 目录；要稳妥就用 appdir() 拼绝对路径。envget("USERPROFILE") 能拿到用户目录，把配置存到那里也不错。

11.1 两种 use：尖括号和引号

use 有两条路：

use <stdio.h>;        // 尖括号：系统头文件 → 生成 #include <stdio.h>
use <math.h>;
use "my_helper.h";    // 引号带 .h：自己的头文件 → 生成 #include "my_helper.h"
  • 尖括号里的名字，编译器去系统目录找，像 stdio.h、math.h、string.h。
  • 引号里的名字，先从程序所在目录找，找不到再找系统目录，通常放你自己写的 .h。

use 只能写在文件最上面，要在函数定义之前。

11.2 第三行 use "C_OPED.cash";：打开直通调用

use "C_OPED.cash"; 是个例外：它不是让你自己去翻头文件，而是一次把系统头文件全包含进来、把窗口库全链接上。之后：

效果说明
头文件已经包含不用再写 use <windows.h>;
函数不用声明就能调直接写 GetTickCount()、MessageBoxA(...)
常量要写数值Win32 的 #define 常量（MB_OK 等）在汇编后端不展开，直接写数值（MB_OK=0、MB_OKCANCEL=1）
自动链接窗口库user32、gdi32、comctl32 等不用自己写

代价是：程序变成窗口式程序，运行时不再有黑色控制台窗口，print 的输出也就没地方显示（调试时加 --console，见"拓展与规范"）。

11.3 计时：GetTickCount

GetTickCount() 返回"开机到现在的毫秒数"，是个整数。用它夹住一段代码，两头相减就是耗时：

int 开始 = GetTickCount();
// ……要计时的代码……
int 用时 = GetTickCount() - 开始;

用时 的单位是毫秒。系统计时器的精度大约是 10 到 16 毫秒，所以很短的计算量出来常常是 0。

11.4 原生消息框：MessageBoxA

MessageBoxA(0, "正文", "标题", 0);   // 第 4 个参数 0 = 只放一个"确定"按钮（Win32 里的 MB_OK）

四个参数：窗口句柄（没有就写 0）、正文、标题、按钮和图标选项。0.5.0 直接生成 x86-64 汇编，不走 C 预处理器，Win32 的 #define 常量（MB_OK、MB_OKCANCEL 这类）不会被自动展开，要写它们的数值：MB_OK 是 0，MB_OKCANCEL 是 1。

弹出框以后程序会停在那里，等用户点按钮，再继续往下走。

11.5 调 C 标准库函数：puts 和 strlen

C_OPED.cash 打开以后，标准库函数也能直接调：

use "C_OPED.cash";

function main() {
    string s = "C* 语言";
    puts(s);
    print "字节数 ", strlen(s);
    print "字符数 ", LEN(s);
}

puts 打印一行文字，效果接近 print。strlen 数的是字节数，和 C* 的 LEN 结果一样（一个汉字 3 个字节）。

printf 不要用：这个名字和 C* 自己的 print 太像，编译器会报 不认识的函数 'printf'，是不是想写 'print'？。要格式化输出就用 print，要打一行原始文字就用 puts。

11.6 调用自己写的 C 函数：加头文件，写原型

想把自己写好的 C 函数搬进来，分两步。

第一步：把函数写进一个头文件，比如和程序放同一个目录的 my_lib.h：

/* my_lib.h —— 自己写的工具函数 */
static long long double_it(long long x) { return x * 2; }

第二步：在 .cask 里"引入 + 声明"：

use "my_lib.h";

int double_it(int x);      // 原型：名字和参数要和 my_lib.h 一致

要点有三个：

  • use "my_lib.h"; 负责把内容包含进来。
  • 那一行 int double_it(int x); 是原型声明，告诉编译器"这个函数存在、参数是什么类型"。
  • C* 的 int 对应的 C 类型是 long long，所以头文件里的参数和返回值要写成 long long。

漏了原型，编译器会提示 不认识的函数 'double_it'（如果它来自 'use' 的头文件，请先声明: ...）。另外，自定义头文件要和生成的可执行文件放在同一个目录，否则编译时会报找不到这个头文件。

11.7 类型对照：写错就报错

直通调用时，C* 把值按下面的规则翻译成 C 类型。自己写 C 函数时也要照着对：

C* 类型C 类型说明
intlong long64 位整数
floatdouble双精度小数
stringchar *字符串
charchar单字符
boolint1 表示真，0 表示假
nonevoid无返回值

11.8 C# 用不了

use 只能打开 C 和 C++ 两个世界。C# 和 .NET 没有 C 头文件，不能用 use 引入，也别指望在 .cask 里写 C# 代码。这一章借来的东西，都来自 C 语言这一边。

拓展与规范

窗口程序想保留控制台，编译时加 --console。 加了这个参数，print 的输出就能在黑色窗口里看到，调试特别有用：

bin\caskc.exe report.cask --run --console

直通调用不检查参数。 C* 只确认名字能对上系统里的某个符号；参数个数和类型由后面的 C 编译器把关。所以报错信息长得像 C 编译器的报错，但行号仍然指回你的 .cask：

report.cask: In function '__cask_start':
report.cask:4:2: error: too few arguments to function 'MessageBoxA'

标准库函数不要自己写原型。 如果你在 .cask 里写 int puts(string s);，会和系统头文件里已有的声明冲突：

error: conflicting types for 'puts'; have 'long long int(char *)'

C_OPED.cash 已经把标准头文件包含好了，标准库函数直接用；只有自己写的 C 函数才需要写原型。

报错时先把 use 那一行检查一遍。 见到 不认识的函数 'xxx'（如果它来自 'use' 的头文件，请先声明: ...），依次确认三件事：头文件加没加、原型写没写、名字拼对没有。

借来的东西越多，程序越只认 Windows。 用了 MessageBoxA、GetTickCount 这类系统函数，程序就绑死在 Windows 上了。写通用的练习时，能用 C* 自带函数就用自带的。

参数顺序要查文档。 Win32 函数有一千多个，C* 不替你背。用哪个、参数什么顺序、常量怎么拼，去查函数说明或 MSDN，抄准了再用。

本章小结

  • use <名字>; 引系统头文件，use "名字.h"; 引自己的头文件，都写在文件最上面。
  • use "C_OPED.cash"; 一次打开 C / C++ / Win32：头文件全包含、库全链接、函数不用声明就能调。
  • GetTickCount() 取毫秒计数，两头相减就是耗时；计时器精度约十几毫秒。
  • MessageBoxA(0, 正文, 标题, 0) 弹原生消息框；第 4 个参数是按钮选项（Win32 里 MB_OK=0、MB_OKCANCEL=1），汇编后端要写数值。
  • puts、strlen 这些标准库函数可以直接调；printf 因为和 print 撞名不能用。
  • 调自己写的 C 函数要两步：use "xxx.h"; 加一行 int 函数名(...); 原型。
  • 直通调用 C* 不查参数，类型错误由 C 编译器报，行号仍指回源文件。
  • C# / .NET 用不了。

开始时刻 = GetTickCount();

run();

读 readtext(应到框) 得到的是文字，用 VALUE 转成整数。用户误删了默认值，就回落到 60。

13.3 网络与攻防：C_NET.cash

use "C_NET.cash";

分四组。前两组是纯计算，不碰网络，随时能跑；第三组会开 socket、只读探活；第四组是主动侦察（会连出去读回数据），只对有权访问的目标用。

协议校验（判断网址、IP 写得对不对）：

函数作用例子
isurl(文字)以 http:// 或 https:// 开头才算合法网址isurl("https://a.com") → 1
isip(文字)严格 IPv4 点分十进制（每段 0..255）isip("256.1.1.1") → 0
urlhost(网址)取主机名（自动去掉端口）urlhost("https://a.com:8443/x") → "a.com"
urlport(网址)取端口，没写按 https=443 / http=80urlport("https://a.com") → 443

编码与完整性（把内容编码、算哈希、base64 往返）：

函数作用例子
fnv1a(文字)32 位 FNV-1a 哈希，同一输入永远同一输出用它发现"内容被改过"
base64(文字)把文字编码成 base64 字符串base64("hello") → "aGVsbG8="
unbase64(文字)把 base64 解码回原文（失败给 ""）编码再解码能还原

主机探测（会用 socket，可能阻塞到约 3 秒）：

函数作用说明
hostalive(主机, 端口)某主机某端口的 TCP 通不通通 1，不通 0；离网给 0，不崩

hostalive 是只读探测：它去连一下对方端口，看能不能建立连接，不发包攻击、不开监听。离网时返回 0，程序照跑。

主动侦察层（bannerget / httpcode / dnsresolve）：

这是"攻防"里真正会主动连出去的部分，对应渗透测试里的"服务发现 / 攻击面识别"。它们都只对"你有权访问的目标"使用，动作和用浏览器打开一个页面在同一量级。

函数作用说明
bannerget(主机, 端口, 探测串)连上服务、发探测串、读回第一行响应拿"服务指纹"（FTP/SMTP/自研服务的 banner）；连不上给 ""
httpcode(网址)对 http:// 发一次 GET，返回状态码200/403/404…；只认明文 http，https 或连不上给 0
dnsresolve(主机)主机名解析成点分 IP本身是 IP 就原样返回；解析失败给 ""

一次典型的"本地体检"（对 127.0.0.1 上做，不碰外网）：

// 本地网络体检：C_NET.cash 主动侦察层
use "C_NET.cash";

function main() {
    // 1) 抓本地 9000 端口某个自研服务的 banner（没有就返回 ""，不崩）
    string 指纹 = bannerget("127.0.0.1", 9000, "help\r\n");
    print "服务指纹：", 指纹;
    // 2) 取本地 8000 上 HTTP 服务的状态码
    print "HTTP 状态：", httpcode("http://127.0.0.1:8000/");
    // 3) 把主机名解析成 IP（IP 原样返回，域名查 DNS）
    print "localhost -> ", dnsresolve("localhost");
    return 0;
}

教学边界：这三个函数"主动"但"只读"——它们连接、读取、解析，不修改目标、不发洪水、不扫漏洞、不做注入。和 hostalive 一样会阻塞（约 3~4 秒），别在界面主循环里高频调用。真实项目里请只对实验室、127.0.0.1、或你已获书面授权的目标使用。

注意 base64 再 unbase64 能原样还原，这是"编码—解码"往返的典型用法；fnv1a 对同一段文字永远给同一个数，所以可以用它当"内容指纹"——文件被改过一点点，哈希就变了。

13.6 便携化与本机端口探测

// 便携小工具：C_SC.cash + C_IO.cash 综合

use "C_IO.cash";

function main() {

    else { print "exe 目录不可写，改用 C_IO 写到用户目录"; }
    if (is64bit() == 1) { print "64 位环境"; }
    else { print "32 位环境"; }
    print "空闲内存：", freebytes(), " 字节";
    print "exe 所在盘空闲：", diskfree(appdir()), " 字节";
    // 把一个辅助文件写到 exe 旁边，再用 C_IO 读回验证
    if (copytoexe("_probe.txt", "pong") == 1) {
        print "写文件成功，读回：", readfile(appdir() + "/_probe.txt");

    return 0;
}

拓展与规范

  • 机器相关的值只展示、不写死。 os_cpu() / os_hostname() / os_ram() 换台机器就变，判断只判断"非空 / 非 0"，别拿具体型号去 ==。
  • C_NET 分"被动"和"主动"两层。 被动层（isurl / isip / fnv1a / base64 / hostalive）随时能用；主动层（bannerget / httpcode / dnsresolve）会连出去读回数据，只对实验室、127.0.0.1、或已获授权的目标用，且保持"只读"——不发包攻击、不发洪水、不做漏洞利用。
  • 探测 / 侦察类函数会阻塞（hostalive / bannerget 约 3~4 秒、portcheck / portscan 逐个拨号），别在界面主循环里高频狂调。
  • 绿色版先判 isportable()。 为 1 才把缓存/配置写 exe 旁边；为 0（如装在 C 盘系统目录）就退回 C_IO 的 envget("USERPROFILE") 写用户目录。
  • 三个头都能单独给控制台用，不依赖窗口；要放进界面再叠 C_OPED.cash + C_CSS.cash。

  • C_OS.cash 读系统：os_pid / os_cores / os_ram / os_cpu / os_hostname / os_platform / isadmin / uptime / findproc。

B.2 严重错误（E）

E|2|18|不能把 string 放进 int

把字符串塞进了整数。改法：确认两边类型一致，用 VALUE 转换，或者把这个变量改成 string。

E|3|15|参数 1（LEN()）应该是 string，但实际是 int

LEN() 要的是字符串，给的是整数。改法：传字符串，或者换成适合数字的函数。

E|3|19|'i' 在这里已经声明过了

同一层里 i 声明了两次，常见于两个 for (int i = ...)。三种改法：先声明 int i; 两处都用 for (i = ...)；起两个不同的名字；或者给其中一个循环套一层 { }。

S|3|34|这里要写 ';'，它要写在 print 后面，但是碰到了 '；'

分号写成了全角 ；。改法：切到英文输入法，用半角 ;。中文标点在代码里一律不能用。

S|2|5|这里要写 ';'，它给这条声明收尾，但是碰到了 'print'

上一行少写了分号，编译器读到下一行的 print 才发现。改法：给上一行补分号。报错的行不一定是真正出错的行，凡是提示 这里要写 ';' 却看不出问题的，往上一行找。

P|3|11|不认识的名称 '成积'，是不是想写 '成绩'？

  3. 双击问题面板里的一条，跳到出错行，重点看这一行和上一行。

C.3 同一段程序的两种写法

C* 原文：

int 单价 = 3;

function main() {
    int 数量 = 4;
    print "总价 ", 单价 * 数量;
}

生成的 C（节选）：

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "cask_rt.h"

#line 1 "c3.cask"
long long 单价 = (3LL);

#line 3 "c3.cask"
static int __cask_start(void)
{

#line 4 "c3.cask"
	long long 数量 = 4LL;

#line 5 "c3.cask"
	cask_p_str("总价 ");
	cask_p_num(cask_mul(单价, 数量, __FILE__, 5));
	cask_nl();
	return 0;
}
int main(void)
{
	cask_init(65001);
	return __cask_start();
}

要看的几点：

  • int 变成了 long long，常量带上了 LL。
  • print 拆成了 cask_p_str、cask_p_num，最后加一个 cask_nl() 换行。
  • 乘法变成了 cask_mul(单价, 数量, __FILE__, 5)，多传了文件名和行号——越界、溢出、除零的报错就是从这里拿到位置的。
  • #line 让 C 编译器报错时指向 .cask 源文件，而不是生成的 .c。

C.4 编译命令

想看等价 C：

bin\caskc.exe 程序.cask --emit-c out.c

注意：--emit-c 只是写出一份等价的 C 给你对照，它本身不编译。真正生成 .exe 走的是汇编后端，-v 能看到实际执行的两条命令，大致是：

as --64 out.gen.s -o out.gen.o
ld -m i386pep --subsystem console -o "out.exe" "…\crt2.o" out.gen.o "…\libcastrt.a" -L "…" -lmingw32 -lgcc -lmingwex -lmsvcrt -lkernel32

窗口程序会把子系统换成 windows，并额外链接一组窗口库：

-luser32 -lgdi32 -lcomctl32 -lole32 -luuid -lshell32 -lcomdlg32 -lmsimg32

libcastrt.a 是工具链在 build.bat 时预编译好的运行时库（含 cask_rt.h / C_OPED.cash / C_CSS.cash / C_IO.cash 的实现），用户机器上编译 .cask 不需要 gcc、g++。

C.5 从 C* 转到 C 要注意

  • C* 的越界、溢出、除零检查，到了 C 里全都没有；C 出这类问题是未定义行为，可能不报错、可能乱跑。
  • 字符串在 C 里就是 char *，长度要自己算，内存要自己管。
  • bool 在 C 里是 int，打印要用 cask_p_bool，不能当普通整数随便打。
  • C 的 printf 格式必须自己配对（%lld 对 long long），配错了不报错，直接输出乱码。

// inventory.cask —— 简易库存管理（控制台）
constant int 最多 = 50;

string 品名[50];
int 单价[50];
int 库存[50];
int 种类 = 0;

int 找位置(string 名) {
    int i;
    for (i = 0; i < 种类; i++) {
        if (品名[i] == 名) { return i; }
    }
    return -1;
}

function 入库() {
    if (种类 >= 最多) {
        print "库位已满，不能再加新品种。";
        return;
    }
    string 名;
    show "品名：";
    input 名;
    int 量;
    int p = 找位置(名);
    if (p >= 0) {
        show "已有该品种，本次入库数量：";
        input 量;
        库存[p] += 量;
        print 名, " 入库 ", 量, "，现有 ", 库存[p];
    } else {
        show "入库数量：";
        input 量;
        show "单价：";
        input 单价[种类];
        品名[种类] = 名;
        库存[种类] = 量;
        种类++;
        print "新增品种 ", 名, "，库存 ", 量;
    }
}

function 出库() {
    string 名;
    show "出库品名：";
    input 名;
    int p = 找位置(名);
    if (p < 0) {
        print "没有这种品名：", 名;
        return;
    }
    int 量;
    show "出库数量：";
    input 量;
    if (量 > 库存[p]) {
        print "库存不足，目前只有 ", 库存[p];
        return;
    }
    库存[p] -= 量;
    print 名, " 出库 ", 量, "，剩余 ", 库存[p];
}

function 查询() {
    string 名;
    show "查询品名：";
    input 名;
    int p = 找位置(名);
    if (p < 0) {
        print "没有这种品名：", 名;
        return;
    }
    print 品名[p], " 单价 ", 单价[p], " 元，库存 ", 库存[p];
}

function 列出() {
    if (种类 == 0) {
        print "库房是空的。";
        return;
    }
    int i;
    for (i = 0; i < 种类; i++) {
        print 品名[i], " 单价 ", 单价[i], " 元，库存 ", 库存[i];
    }
}

function 统计() {
    if (种类 == 0) {
        print "库房是空的。";
        return;
    }
    int 总数量 = 0;
    int 总价值 = 0;
    int 最多库存 = 库存[0];
    int 最多位置 = 0;
    int i;
    for (i = 0; i < 种类; i++) {
        总数量 += 库存[i];
        总价值 += 库存[i] * 单价[i];
        if (库存[i] > 最多库存) {
            最多库存 = 库存[i];
            最多位置 = i;
        }
    }
    print "品种 ", 种类, "，总数量 ", 总数量, "，总价值 ", 总价值, " 元";
    print "库存最多的是 ", 品名[最多位置], "（", 最多库存, " 件）";
}

function main() {
    print "==== 简易库存管理 ====";
    int 选择 = -1;
    while (选择 != 0) {
        print "1 入库  2 出库  3 查询  4 列出  5 统计  0 退出";
        show "请选择：";
        input 选择;
        if (选择 == 1) { 入库(); }
        else if (选择 == 2) { 出库(); }
        else if (选择 == 3) { 查询(); }
        else if (选择 == 4) { 列出(); }
        else if (选择 == 5) { 统计(); }
        else if (选择 == 0) { print "再见。"; }
        else { print "没有这个选项，请重选。"; }
    }
}

        alert("姓名不能为空。");

    if (分数 < 0 or 分数 > 100) {
        alert("分数要在 0 到 100 之间。");
        return;

    人数 = 人数 + 1;
    总分 = 总分 + 分数;
    if (人数 == 1) {
        最高分 = 分数;
        最低分 = 分数;
    }
    if (分数 > 最高分) { 最高分 = 分数; }
    if (分数 < 最低分) { 最低分 = 分数; }

附录 F　彩蛋与暗号：rcl()

F.2 任务引入

机房里几个同学一起写一个"库存小工具"，约定了一个只有组内人才知道的口令：

  • 输入 235，或者 FC235、JF235 这类暗号，程序回一句自己人看得懂的话；
  • 输入别的，程序装作什么也没发生，照常干活；

rcl 就是 C* 为这种需求准备的内置函数。它不用 use，也不用自己写函数体，直接调用就行。

F.3 知识准备：rcl 的三条规矩

写法结果
rcl();输出一行 rcl永远爱方程235！，然后立刻结束整个程序，它后面的语句一句都不执行

一句话记住：空着调用是"说完就走"，对上暗号是"回一句"，别的值就是"没听见"。

参数类型认得的写法
数字235（写成 235.0 的小数也认）

另外三条附带说明，写错的时候用得上：

  • rcl 的返回值是整数（int）0，所以 int 结果 = rcl(235); 是合法写法，只是没人关心这个 0。
  • 给两个参数会报错：rcl() 要么不写参数、要么写一个值，这里是 2 个。

    print "这一句不会执行";
}

function main() {
    print "开始";
    内层();
    print "这一句也不会执行";
}

写法结束谁适合用在哪
return; / return 0;只结束当前这个函数，回到调用它的地方继续正常的函数返回、参数不合法时提前退出

        input 命令;

        print "收到：", 命令;

F.6 任务实施三：给考勤登记藏一个暗号

最后把它用进第 12 章那种窗口程序里。这次暗号是学号 235：填这个学号不走正常登记，而是打开"开发者模式"。

use "C_OPED.cash";

int 姓名框;
int 学号框;
int 名单框;
int 状态标签;
int 登记条数 = 0;

function 刷新状态() {
    settext(状态标签, "已登记 " + 登记条数 + " 条");
}

function 登记(string 姓名, string 学号) {
    settext(名单框, readtext(名单框) + 学号 + " " + 姓名 + "\r\n");
    登记条数 = 登记条数 + 1;
    刷新状态();
}

function on_click(int 控件) {
    string 姓名 = readtext(姓名框);
    string 学号 = readtext(学号框);
    if (LEN(学号) == 0) { settext(状态标签, "学号不能为空"); return; }
    if (VALUE(学号) == 235) {                 // 隐藏暗号：学号填 235
        rcl(235);                             // 说一句「rcl 爱 方程235」
        settext(状态标签, "开发者模式已打开");
        return;
    }
    登记(姓名, 学号);
}

function main() {
    window("机房考勤登记", 520, 430);
    label("姓名", 20, 24, 60, 24);
    姓名框 = textbox("", 80, 22, 150, 26);
    label("学号", 250, 24, 60, 24);
    学号框 = textbox("", 310, 22, 150, 26);
    button("登记", 20, 64, 120, 32);
    名单框 = memo("", 20, 110, 460, 230);
    状态标签 = label("已登记 0 条", 20, 350, 300, 24);
    run();
}

这里有两点和前面不同，交付时要跟同学讲清楚：

  • 窗口程序默认没有控制台，rcl 打的那行字看不见。想看到它，编译运行时加 --console：bin\caskc.exe 考勤.cask --run --console。如果希望不依赖控制台，把暗号的反馈写在界面上（上面用 settext(状态标签, …) 就是这么做的）。
  • 暗号判断要放在正常流程之前，判断成立后 return，这样彩蛋就不会污染正常登记逻辑。

F.7 拓展与规范

彩蛋代码和业务代码混在一起，很容易变成"没人看得懂的怪代码"。下面几条是交付经验：

  • 彩蛋要能被一眼认出来：包成单独的函数（比如 隐藏口令(口令)），加一行注释说明它是彩蛋，别把 rcl 散落在业务逻辑里。
  • 不要用 rcl() 当正常退出：业务程序该保存的保存、该关的关，rcl() 会跳过全部收尾代码，只适合急停和演示。
  • 别用它绕开循环：从 while (true) 里退出应该用条件判断或 break，rcl() 是"把程序整个关掉"，不是"结束循环"。
  • 交付说明里写一句：如果有暗号，在 README 或演示文档里写一句"输入 235 有惊喜"，不然下一个维护的人只会以为程序写错了。
  • 注意版本：rcl 是 0.5.0 的内置函数。把程序交给别人之前，用 bin\caskc.exe --version 确认对方也是 0.5.0，否则会报"未知函数"。
  • 别忘了测试：暗号分支也要跑一遍，确认它对上暗号时只是多说一句话，不会破坏正常功能。

F.8 本章小结

想做的事写法
立刻结束整个程序（并留一句话）rcl();
对上随机值暗号rcl(235);
对上字符串暗号rcl("FC235"); 或 rcl(口令);
什么也不做rcl(别的值);
让用户输入的文字能按数字比对VALUE(文字)

rcl 不改变程序的业务逻辑，它只是给程序留了一个只有自己人才知道的入口。用得好是彩蛋，用不好是坑。
